# LottoCube · 3D & 2D Analytics

React + TypeScript SPA / PWA สำหรับวิเคราะห์สถิติหวยไทยจากข้อมูลจริงย้อนหลัง 10 ปี รองรับไทย/อังกฤษและธีมตามระบบ สว่าง หรือมืด

## เริ่มใช้งาน

เครื่องนี้ติดตั้ง `.venv` และแพ็กเกจ Python ไว้แล้ว:

```powershell
npm.cmd install
npm.cmd run dev
```

คำสั่งเดียวเปิด Vite และบริการข้อมูล Python พร้อมกัน เปิด URL ที่ Vite แสดง (ปกติ http://127.0.0.1:5173) หากมี dev server เก่าทำงานอยู่ ให้หยุดแล้วเริ่มใหม่ด้วยคำสั่งนี้เพื่อให้บริการข้อมูลเริ่มด้วย

เครื่องใหม่ต้องมี Node.js 22+ และ Python 3.10+:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r scripts\requirements.txt
npm.cmd install
npm.cmd run dev
```

macOS / Linux ใช้ `.venv/bin/python` แทน `.\.venv\Scripts\python.exe` และใช้ `npm` แทน `npm.cmd`

## ข้อมูลจริงและการอัปเดตอัตโนมัติ

- ใช้ [data/lotto-history.json](data/lotto-history.json) โดยตรง ไม่ใช้ชุดตั้งต้น 24 งวด ข้อมูลที่ดึงวันที่ 5 พฤศจิกายน 2569 มี **238 งวด** ตั้งแต่ 16 พฤศจิกายน 2559 ถึง 1 พฤศจิกายน 2569 ตามรายการจริงของ [Sanook](https://news.sanook.com/lotto/archive/) จำนวนงวดไม่จำเป็นต้องเท่ากับ 240
- เมื่อเปิดแอป กลับมาที่หน้าต่าง กลับมาออนไลน์ หรือใช้งานอยู่ แอปตรวจ `/api/history` อัตโนมัติ ข้อมูลเดิมแสดงทันที การตรวจซ้ำจากหน้าต่างเดิมเว้นอย่างน้อย 30 วินาที และตรวจระหว่างใช้งานทุก 60 วินาที
- เซิร์ฟเวอร์ตรวจหน้ารายการล่าสุด ไม่เดาวันออกรางวัลจากวันที่ 1/16 จึงรองรับงวดเลื่อนและข้ามงวดที่ยังประกาศไม่ครบ
- ใช้ [data/lotto-history.meta.json](data/lotto-history.meta.json) เป็นรายการวันที่ที่เก็บครบจากแหล่งข้อมูล หากงวดล่าสุดและข้อมูลทุกวันที่ควรมีครบแล้ว **ไม่เรียกกระบวนการดึงย้อนหลังใหม่** และไม่เขียนไฟล์ประวัติซ้ำ
- หากมีงวดใหม่ งวดขาด หรือรางวัลในไฟล์ไม่ครบ จะตรวจรายการย้อนหลังให้ครบสิบปีและบันทึกเฉพาะข้อมูลที่ผ่านการตรวจ บันทึกแบบ atomic พร้อมสำรองไฟล์เดิมเป็น `.bak`
- คำขอพร้อมกันใช้ lock เดียว เซิร์ฟเวอร์พักการตรวจซ้ำ 120 วินาที ทั้งกรณีสำเร็จและล้มเหลว หากแหล่งข้อมูลล่มจะส่งข้อมูลเดิมพร้อมสถานะ stale และลองใหม่ภายหลัง
- ข้อมูลส่วนกลางอยู่ในไฟล์บนเซิร์ฟเวอร์ ส่วนรายการที่ผู้ใช้เพิ่ม/นำเข้าและการตั้งค่าอยู่ใน localStorage ของอุปกรณ์ การอัปเดตอัตโนมัติรักษารายการส่วนตัวไว้
- ย้ายข้อมูลจากคีย์เดิม `lottolab.draws.v1` มายังคีย์ `lottocube.draws.v1` โดยเก็บคีย์เดิมไว้ ชุด seed เก่าถูกแทนด้วยฐานจริง หากอ่าน storage ไม่ได้จะสำรองเป็น `.recovery` ก่อนบันทึก
- ยังคงเพิ่มเอง นำเข้าแบบตรวจสอบก่อนแทนที่ และส่งออก JSON ได้

ดึงหรือซ่อมฐานข้อมูลผ่าน CLI ได้เช่นกัน:

```powershell
.\.venv\Scripts\python.exe scripts\fetch_lotto.py --years 10 --ensure
```

ใช้ `--years 10` เพื่อสแกนใหม่ทั้งช่วง หรือ `--draws 24 --output data/latest-24.json` เมื่อต้องการไฟล์แยก ตัวเลขถูกเก็บเป็น string เพื่อรักษาศูนย์นำหน้า ไม่มีการสุ่มหรือเดาผลรางวัล รองรับรูปแบบปัจจุบันที่มีหน้า/ท้าย 3 ตัวอย่างละสองชุด

## PWA และการนำขึ้นใช้งาน

```powershell
npm.cmd run build
npm.cmd run start
```

เปิด http://127.0.0.1:4173 เพื่อตรวจเวอร์ชัน production พร้อม API การนำขึ้นใช้งานจริงต้องเปิดบริการ Python ควบคู่และให้ HTTPS reverse proxy ส่งทั้งหน้าเว็บและ `/api/history` มายังบริการเดียวกัน ต้องเก็บโฟลเดอร์ `data/` บนดิสก์ที่เขียนได้ ไม่ใช่ฝากไฟล์ static อย่างเดียว

Android / Chrome ใช้ปุ่ม **ติดตั้งแอป** เมื่อเบราว์เซอร์รองรับ ส่วน iPhone / iPad ใช้ Safari → แชร์ → เพิ่มไปยังหน้าจอโฮม การติดตั้งต้องใช้ HTTPS หรือ localhost

Service worker แคชตัวแอป ฟอนต์ไทย/อังกฤษ และไอคอน หลังเปิดออนไลน์ครั้งแรกสามารถปิดแล้วเปิดซ้ำแบบออฟไลน์ได้ ข้อมูลล่าสุดที่บันทึกไว้ยังวิเคราะห์ได้ ส่วน API ไม่ถูกแคชเป็นผลตรวจใหม่ หากมีตัวแอปเวอร์ชันใหม่จะมีปุ่มให้เลือกใช้เวอร์ชันใหม่ การเปลี่ยนภาษาและธีมไม่รีโหลดหน้าและรักษาตัวกรอง/ข้อมูลไว้

## โครงสร้าง

```text
data/                  ประวัติจริงและรายการตรวจความครบถ้วน
scripts/fetch_lotto.py  อ่าน Sanook ตรวจข้อมูล และบันทึก
scripts/serve_lotto.py  API ตรวจ/เติมข้อมูลและเสิร์ฟ production
scripts/run.mjs        เปิด frontend/backend ด้วยคำสั่งเดียว
scripts/pwa.mjs        สร้าง service worker จากไฟล์ build จริง
src/data/history.ts    อ่าน JSON เป็นฐานข้อมูลของ React
src/components/        หน้าจอและ UI ร่วม
src/hooks/             ข้อมูลอัตโนมัติ, URL state, PWA
src/lib/               สถิติ ตรวจข้อมูล และคำแปล en.json
src/styles.css         ฟอนต์, tokens, light/dark, responsive
public/                manifest และไอคอน PWA
tests/                 browser, accessibility และ offline PWA
```

## ตรวจสอบ

```powershell
npm.cmd test
npm.cmd run typecheck
npm.cmd run build
npm.cmd run test:e2e
npm.cmd run format:check
.\.venv\Scripts\python.exe -X utf8 -m unittest discover -s scripts -p "test_*.py"
```

E2E ใช้ Chrome ในเครื่อง กำหนด `CHROME_PATH` หาก executable อยู่ตำแหน่งอื่น รัน build ก่อน E2E เพราะมีการทดสอบ PWA production บนพอร์ต 4173

คะแนนเป็นดัชนีจากความถี่ในอดีต ไม่ใช่เปอร์เซ็นต์โอกาสถูกรางวัล ใช้เพื่อการศึกษาและไม่รับประกันผลในอนาคต หากตรวจรางวัลควรตรวจซ้ำกับสำนักงานสลากกินแบ่งรัฐบาล
